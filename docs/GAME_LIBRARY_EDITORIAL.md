# 低门槛游戏图鉴：内容与权利审核规范（规划，不代表已上线）

## 产品边界

图鉴将同时覆盖 **零道具**（口头、手势、徒手）和 **普通／可自制材料**（纸笔、硬币、普通扑克／骰子、打印组件）的线下游戏。图鉴负责教会玩家准备和开局；计时、计分、随机、私密发牌与主持提示按需唤起现有桌游助手。不要把每款游戏做成一套自动裁判，不要求账号或云同步。首个已实现的通用私密发牌入口不构成任何具体游戏的授权或收录。

## 候选游戏数据契约（未来图鉴条目）

每项候选保留稳定 ID、原创展示标题、其他常见名称及对应语言、原始资料出处；记录：

- 玩法：人数区间、估计准备与游戏时间（注明编辑估计或试玩样本）、建议年龄及依据（阅读／计算／动作需求）、合作或竞争、适合场地与空间、活动／身体接触／出局机制、可访问性提示。
- 材料：`none`／普通材料／可打印／自制材料，逐项说明替代方案、制作步骤及可下载文件的权利依据；零道具条目不强制材料清单。
- 教学：一句话目标、设置、回合／动作顺序、结束与胜负条件、自写完整说明、原创例子、常见疑问、可选变体（必须与基础规则明确区分）。
- 助手：只记录需要的通用工具和配置，不要求玩家在数字端执行每一步。
- 审核：`draft`、`rights-review`、`ready`、`blocked` 状态，逐项来源链接及访问日期、权利人或出处、适用地区、文本／图片／图标／棋盘／卡牌／名称等各自的权利依据、许可范围及商业使用／署名／改编要求、审核人及日期、疑虑与结论依据。

## 正式发布门禁

1. **不以“古老”“民间流传”“玩法相似”推定无版权。** 抽象机制、具体文字和插图、现代版本的角色／卡面／棋盘设计、名称和商标，必须分开核查；还须考虑其他适用的知识产权与不正当竞争风险。规则来源可用于事实核验，但不得直接转载别人的说明书或词库。
2. 有文档支持的公有领域、权利人允许的兼容许可、或可证明独立创作的文本和素材才可以进入对应的发布审核；许可需检查商用、再分发、改编、署名和地域条件。无法判断时保持 `rights-review` 或 `blocked`，必要时征求合格法律专业人士意见。`ready` 表示内部审核通过，不代表对外担保“绝对无版权／零风险”。
3. 每条必须有人审阅原文、重新独立撰写教学和例子、进行实际试玩验证，并逐项记录审阅和证据。年龄／时长未实测时明确标为估计，不能引用商业盒装参数假装自己测过。
4. **只发布 `ready` 且证据完整的条目。** 不能因为候选存在而自动生成公开页面或游戏包；第三方投稿和用户自定义内容默认仅留在本机，不自动出现在公共目录。
5. 狼人杀、谁是卧底等具体名称／现代版本、现成角色牌和词库全部先视为 *待核实候选*。首版通用私密发牌工具不预装这些名称、角色、图、台词或词语。
6. 发现权利异议时立即暂停相关条目的公开分发，保留来源与审阅记录，核查后再决定修订、授权或下架。

## 先行的私密发牌／主持工具的安全边界

- 玩家自行输入一人一行名单、每人一条私密内容（重复内容需重复写），使用浏览器安全随机源无放回分配；不提供具体游戏的规则、角色卡、默认词库。
- 必须依次 **交给玩家 → 玩家主动揭示 → 遮住**；遮住后不可在 DOM 中残留上一人的私密内容。公开主持提示由用户自行输入，且不得包含秘密；不自动判胜。
- 私密内容仅在当前页面内存中；关闭或刷新清除，不写入 localStorage、Table OS 备份、历史摘要、剪贴板或网络。切到后台会重新遮蔽已经揭示的内容。使用者仍须防止旁观者窥屏、截屏或设备系统备份等工具无法控制的风险。
- 首版独立于已有 Table OS 数据模型，避免自动覆盖或继承现有私人身份；如未来需要互通，必须单独设计明确的迁移、确认和回归测试。

本文件是产品审核流程与实现边界，**不是对任何具体游戏作出的法律认定**。路线跟踪见 Issue #53；商店发布与签名另见 Release Gate #14。
